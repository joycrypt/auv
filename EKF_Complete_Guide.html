1. Overview of Extended Kalman Filter

1.1 What is an Extended Kalman Filter?

The Extended Kalman Filter (EKF) is an optimal state estimation algorithm that fuses measurements from multiple sensors to estimate the state of a nonlinear dynamical system.

Key Characteristics:

  • Recursive: Updates state estimate with each new measurement
  • Optimal: Minimizes estimation error in least-squares sense
  • Probabilistic: Maintains uncertainty (covariance) of estimates
  • Nonlinear: Handles nonlinear dynamics via linearization

1.2 Why Use EKF for AUV Navigation?

Sensor Provides Limitation
IMU High-rate attitude & acceleration (100 Hz) Drifts over time (integration errors)
DVL Accurate velocity (10 Hz) Lower rate, occasional dropouts
GPS/USBL Absolute position (1 Hz) Low rate, ±0.5m accuracy
Depth Accurate depth (2 Hz) Only vertical position
Magnetometer Heading reference (5 Hz) Subject to magnetic disturbances
EKF Solution: Combine all sensors optimally to get:
  • High-rate estimates (100 Hz from IMU)
  • No drift (corrected by GPS/DVL/Depth)
  • Low uncertainty (optimal fusion)

│                    (Runs at 100 Hz)                         │
└─────────────────────────────────────────────────────────────┘
                            │
            ┌───────────────┴──────────────┐
            ▼                              ▼

    ┌──────────────────┐              ┌──────────────────┐
    │  PHASE 1:        │              │  PHASE 2:        │
    │  PREDICT         │              │  UPDATE          │
    │  (Time Update)   │              │  (Measurement)   │
    └──────────────────┘              └──────────────────┘
    │                                  │
    │ Input: IMU                       │ Input: DVL/GPS
    │  • ax, ay, az                    │  • Velocity
    │  • gx, gy, gz                    │  • Position
    │                                  │  • Depth
    │ Process:                         │
    │  1. State dynamics               │ Process:
    │     x⁻ = f(x, u, dt)             │  1. Innovation
    │                                  │     y = z - h(x⁻)
    │  2. Jacobian                     │  2. Kalman Gain
    │     F = ∂f/∂x                    │     K = P⁻Hᵀ(HPH'+R)⁻¹
    │                                  │  3. Correct state
    │  3. Covariance                   │     x⁺ = x⁻ + Ky
    │     P⁻ = FPFᵀ + Q                │  4. Update covariance
    │                                  │     P⁺ = (I-KH)P⁻(...)ᵀ
    │                                  │
    │ Output:                          │ Output:
    │  • Predicted state x⁻            │  • Corrected state x⁺
    │  • Uncertainty grows ↑           │  • Uncertainty shrinks ↓
    │                                  │
    └──────────────┬───────────────────┘
                   │
                   ▼
            Next iteration
             (0.01s later)

2.1 Phase 1: PREDICT (Propagation)

Purpose: Use IMU measurements to predict state forward in time

Frequency: Every cycle (100 Hz)

Effect: State evolves according to dynamics, uncertainty increases

State Prediction (Nonlinear):
x⁻k = f(xk-1, uk, dt)

Where:
• ṗ = Rbn(η) · vbody
• v̇ = Rbn(η) · abody - [0, 0, g]ᵀ
• η̇ = W(φ,θ) · ωbody
Covariance Prediction (Linearized):
P⁻k = Fk Pk-1 Fkᵀ + Qk

Where F = ∂f/∂x (Jacobian matrix)

2.2 Phase 2: UPDATE (Correction)

Purpose: Use sensor measurements (DVL, GPS, Depth) to correct prediction

Frequency: When measurements arrive (1-10 Hz)

Effect: State corrected toward measurement, uncertainty decreases

Innovation (measurement residual):
yk = zk - h(x⁻k)

Innovation Covariance:
Sk = Hk P⁻k Hkᵀ + Rk

Kalman Gain:
Kk = P⁻k Hkᵀ Sk⁻¹

State Update:
xk = x⁻k + Kk yk

Covariance Update (Joseph Form):
Pk = (I - KkHk) P⁻k (I - KkHk)ᵀ + Kk Rk Kkᵀ

4. Key Formulas and Equations

4.1 State Dynamics (Nonlinear)

Position dynamics:
ṗ = Rbn(η) · vbody

Where Rbn is the rotation matrix from body to navigation frame.
Velocity dynamics:
v̇ = Rbn(η) · abody - [0, 0, g]ᵀ

Gravity g = 9.81 m/s² acts in +Z (down) direction in NED frame.
Attitude dynamics (Euler angles):
η̇ = W(φ,θ) · ωbody

Where:
W(φ,θ) = [ 1 sin(φ)tan(θ) cos(φ)tan(θ) ]
         [ 0 cos(φ) -sin(φ) ]
         [ 0 sin(φ)/cos(θ) cos(φ)/cos(θ) ]

4.2 Rotation Matrix (ZYX Euler Convention)

Rbn = Rz(ψ) · Ry(θ) · Rx(φ)

= [ cψcθ cψsθsφ-sψcφ cψsθcφ+sψsφ ]
  [ sψcθ sψsθsφ+cψcφ sψsθcφ-cψsφ ]
  [ -sθ cθsφ cθcφ ]

Where c = cos, s = sin

4.3 EKF Predict Equations

State prediction:
x⁻k = f(xk-1, uk, dt)

Covariance prediction:
P⁻k = Fk Pk-1 Fkᵀ + Qk

Where Fk = ∂f/∂x |xk-1 (Jacobian)

4.4 EKF Update Equations

Innovation: yk = zk - h(x⁻k)

Innovation covariance: Sk = Hk P⁻k Hkᵀ + Rk

Kalman gain: Kk = P⁻k Hkᵀ Sk⁻¹

State update: xk = x⁻k + Kk yk

Covariance update (Joseph Form):
Pk = (I - KkHk) P⁻k (I - KkHk)ᵀ + Kk Rk Kkᵀ

6. Kalman Gain Interpretation

6.1 Physical Meaning

The Kalman gain K determines how much to trust the measurement versus the prediction.

K = 0.0 ──────────────── K = 0.5 ──────────────── K = 1.0
│                        │                         │
Trust prediction         Balance both             Trust measurement
completely               equally                   completely
│                        │                         │
Used when:               Used when:                Used when:
• Sensor very noisy      • Similar uncertainty     • Sensor very accurate
• Prediction confident   • Moderate confidence     • Prediction uncertain

6.2 Mathematical Formula

K = P⁻ Hᵀ
    ───────────────
    H P⁻ Hᵀ + R

Interpretation:
  • • Numerator (P⁻): Prediction uncertainty
  • • Denominator: Total uncertainty (prediction + measurement)
  • • K = (prediction uncertainty) / (total uncertainty)

6.3 Examples from Our Calculation

Update Kalman Gain Interpretation
DVL K = 0.990 Trust DVL 99%! It's very accurate (σ=0.02 m/s) and prediction is uncertain (σ=0.2 m/s)
Depth K = 0.9999 Trust depth sensor 99.99%! It's extremely accurate (σ=0.01 m) vs uncertain prediction (σ=1.0 m)
GPS K ≈ 0.8 Trust GPS 80%. It's good (σ=0.5 m) but prediction also has some confidence

6.4 Limiting Cases

Case 1: Perfect sensor (R → 0)
K → 1 (trust measurement completely)
x⁺ = x⁻ + 1·(z - x⁻) = z
State becomes exactly the measurement!

Case 2: Perfect prediction (P⁻ → 0)
K → 0 (ignore measurement)
x⁺ = x⁻ + 0·(z - x⁻) = x⁻
State stays at prediction!

Case 3: Very noisy sensor (R → ∞)
K → 0 (ignore measurement)
Don't trust garbage data!

7. Parameter Tuning Strategy

7.1 The Challenge

EKF performance depends critically on three parameter sets:

  • R (measurement noise): How accurate are sensors?
  • Q (process noise): How good is our model?
  • P₀ (initial covariance): How uncertain is initial state?

7.2 Our Tuning Approach

Step 1: Start with Sensor Datasheets

Step 2: Tune Process Noise

Process noise σproc = 0.01 represents unmodeled dynamics.

Too small (0.001):
  • ✗ Filter overconfident in model
  • ✗ Can diverge if model has errors
  • ✗ Ignores real sensor data

Too large (0.1):
  • ✗ Filter uncertain about everything
  • ✗ Oscillates between measurements
  • ✗ Slow convergence

Just right (0.01):
  • ✓ Trusts model between measurements
  • ✓ Accepts corrections when needed
  • ✓ Fast convergence, low steady-state error

Step 3: Set Initial Covariance

P₀ should reflect actual initial uncertainty:

• Position: ±1.0 m (GPS gives rough start)
• Velocity: ±0.2 m/s (DVL initializes well)
• Attitude: ±4° roll/pitch (from accelerometer), ±13° yaw (from mag)

Too large P₀ → slow convergence
Too small P₀ → filter overconfident, may diverge

8. Common Questions and Answers

Q1: Why not just use GPS alone?

Answer: GPS has three problems for AUV navigation:

  1. Low rate: Only 1 Hz → jerky estimates
  2. Limited accuracy: ±0.5 m → not precise enough
  3. No attitude: Doesn't tell us roll/pitch/yaw

EKF uses IMU (100 Hz) for smooth, high-rate estimates, and GPS (1 Hz) only to correct accumulated drift.

Q2: What happens if DVL drops out for 10 seconds?

Answer: The filter continues predicting using IMU, but velocity uncertainty grows:

After 1 second: σvel ≈ 0.03 m/s (still good)
After 5 seconds: σvel ≈ 0.15 m/s (acceptable)
After 10 seconds: σvel ≈ 0.3 m/s (degraded but usable)

Position uncertainty also grows: Δσpos ≈ σvel · t ≈ 0.03 m/s · 10s = 0.3 m

Key point: Thanks to low process noise (σproc=0.01), drift is slow. System remains functional.

Q3: Why Extended KF instead of standard KF?

Answer: Our dynamics are nonlinear:

  • Rotation matrix Rbn(φ,θ,ψ) involves sin/cos (trigonometric)
  • Euler kinematics W(φ,θ) has tan(θ) (nonlinear)
  • Coupling between position and attitude through Rbn

Standard KF only works for linear systems: xk = A xk-1 + B uk

Extended KF handles nonlinear f(x,u) by linearizing around current estimate at each timestep (computing Jacobian F = ∂f/∂x).

Q4: What's the 180° roll offset about? Is it a bug?

Answer: Not a bug! It's Euler angle ambiguity.

The same physical orientation can be represented two ways:

Representation 1: (φ=1°, θ=2°, ψ=45°)
Representation 2: (φ=179°, θ=178°, ψ=225°)

Both describe nearly identical orientations. The filter uses whichever is closer to its initialization.

Solution: The visualization code handles this automatically (see ekf_visualizer.py line 1099) by adjusting display angles.

Q5: How do you verify the filter is working correctly?

Answer: Check innovation consistency (whiteness test):

Innovations should be zero-mean Gaussian: yk ~ N(0, Sk)

Test: ykᵀ Sk⁻¹ yk ~ χ²m

If this chi-squared statistic is consistently:
  • • Too large: Filter too confident (R or Q too small)
  • • Too small: Filter not confident enough (R or Q too large)
  • • Just right: Filter properly tuned! ✓

Our result: Innovations are small and consistent with predicted covariance S → properly tuned!
